# 日报内容发布与源码提交分离

[English](2026-11-09-content-publication-design.md)

状态：用户于 2026-11-09 要求实施此前讨论的“生成 → 校验 → 不可变内容包 → 固定版本渲染 → 部署 → 线上核对”流程。本文记录实施默认选择；不授权修改生产配置、定时任务、凭据或发送消息。

## 交付结果

保留 Astro 和 GitHub Pages。更新日报、周报时，可以发布新网页，无须把生成的报告、图片和 JSON 加入源码分支。代码变更继续走 PR 和完整源码质量检查；内容变更保留 owner 校验、网页构建、发布回执、永久私有归档及线上日期和摘要核对。

上传成功或 Actions 成功不等于读者已看到正确报告。只有渲染器版本、内容身份、报告和下载链接全部核对通过，才算发布完成。

## 当前情况与方案选择

Platform 负责生成、公开字段投影、报告契约和已安装的快照 CLI；Pages 负责 Astro、页面质量校验、下载和托管 workflow；Deploy 负责三类报告的发布器、持久化状态、归档、投递和定时任务。现在提交到 Git 的是 artifacts/public 输入，构建后的 HTML 已经通过 Actions 产物部署。

| 方案 | 取舍 | 决定 |
| --- | --- | --- |
| 保留日报 PR | 改动少，Git 历史便于追溯；生成数据持续累积，日报要经过源码 CI | 保留为旧流程及恢复路径 |
| 不可变公开内容包、显式部署请求和统一发布协调器 | 复用 GitHub 托管及认证，分离代码和内容；需要共享状态及故障恢复检查 | 实施用户要求的流程 |
| 对象存储/CDN 或动态应用 | 适合大量历史附件、高频更新或私有访问；增加服务和配置 | 后续再考虑 |

实施默认使用现有公开 Pages 仓库的 GitHub Release asset 保存按内容寻址的报告包，不引入新的托管平台。内容使用独立前缀的预发布标签，不替代普通软件 latest release。开发验收不上传真实报告包。

## 归属与合并顺序

Platform 在现有快照 CLI 旁增加标准库内容包 CLI 及公开版本化契约，复用已有投影和校验。压缩包摘要正确不能代替公开资格检查。

Pages 接收核验后的外部输入，分别保留干净的渲染源码身份、已安装 exporter 来源、输入摘要、质量回执和最终输出摘要。不能把报告输入和源码混为一谈。中英文页面及现有 URL 保持原义。

Deploy 调用已安装且固定版本的 owner CLI，不 import 相邻源码。先使用已有 importer 准备当前报告，再由共享协调器发布完整公开快照。原有生成、研究、模型、投递和历史回执不改变归属。

按 Platform provider → Pages consumer → Deploy consumer 顺序合并，记录实际合入版本及共同测试的版本组合。既有生产 release 和 pending 事务保持原状。

## 内容包契约

首版契约为 market_intel.site_content_bundle.v1。包内只包括规范化清单和 Platform 导出的 data/、reports/，不包括源码、私有原始输入、凭据、缓存或可执行 workflow。各报告类别继续遵守原有近五个报告日窗口；不删除历史 Git 或归档。

清单记录 publication=public、候选事务创建时固定的生成时间、实际安装的 producer 源码身份、每个相对文件的 SHA-256 和长度，以及按规范化清单计算的内容标识。压缩包实际字节摘要与逻辑内容标识分别记录，重试复用原包。

默认限制为压缩包 64 MiB、展开合计 256 MiB、单文件 16 MiB、最多 4096 个文件。拒绝重名、未知 schema/字段、绝对路径、点路径、反斜线/盘符路径、软硬链接、设备、未支持类型、错误大小/摘要和额外文件。全部核验后才提升输出，不把任意压缩包直接展开到源码检出。

打包器先调用已有公开快照导出/投影，并在公开上传前核验各报告类别的字段和 schema。原始报告中的私有字段、未索引文件不能因为放进目录就被公开。如果现有 exporter 缺少公开快照校验入口，应补在 Platform，不在 Deploy/Pages 复制报告逻辑。

验证器核对下载字节、清单身份、每个文件及公开资格，再生成适合 owner exporter 的全新外部暂存根目录。原包与再次导出后的规范化结果分开记录摘要。验证导出的快照能够再次被消费，且不丢失已支持报告类别。

## 构建与发布身份

旧源码输入构建保留原有身份 schema。外部内容构建使用增量身份版本，分别记录内容包身份/摘要、producer 版本、原始外部输入、实际导出快照及渲染源码版本。保留现有安装来源/RECORD 检查、-I 隔离、失败时保留原输出、质量校验器绑定和最终摘要核验。

在 /data/site-publication.json 提供简短公开标记，记录候选事务、内容包、渲染版本和真实 Actions run/attempt，不暴露私有路径、投递对象、token 或操作人信息。/data/ 和 /reports/ 下载继续绑定实际校验字节。该标记不能替代报告日期、修订及文件核对。

新发布回执使用明确的 publication_id、renderer_revision 和 bundle 字段，不把包摘要塞进旧 merge_sha，不伪造 commit。旧回执继续按原义读取。

## 内容模式只有一条生产部署路径

只改日报发布器不够：普通代码 push 仍可能用旧 Git 内容重建网站，覆盖新日报。因此内容模式使用一条显式生产 workflow 和一个共享协调器。

仓库级 opt-in 模式默认关闭，旧流程保持不变。启用后，源码 PR/push 仍跑完整检查和预览，但不再自行部署 Git 中的旧报告。协调器即使没有新日报，也会发现已审核的新渲染版本，将其与最近已确认内容一起部署；无需定期提交报告。代码上线最多增加现有发布器轮询间隔的等待。

显式 workflow 只接收不可变内容 asset ID/摘要、候选身份和已合入的渲染版本，不允许任意 URL、仓库、命令、import 或未审核分支。固定仓库下载，先核验大小/摘要，再调用固定版本 owner 复验、构建、做内容/页面冒烟、上传并通过原 github-pages 环境部署。分支和环境保护继续生效。

旧/新部署路径使用共同生产 concurrency 组。单独授权切换时先排空旧任务。GitHub concurrency 不保证 FIFO，排队任务被取消/替换后必须可识别、可恢复；存在可能覆盖新内容的旧 pending 或部署时不能启用新模式。

## 共享协调器与修订

亚洲、美股和周报在内容模式下共用一个明确配置的状态根目录和跨进程仓库锁，不把旧的各类 pending 文件直接解释成新状态。

仅在共享状态为空且操作者明确请求时，才能从已审核的公开快照/渲染版本 bootstrap；已有状态必须核验，不能静默用 Git 旧数据替换。

每个候选从上次已确认的完整公开快照开始，仅调用当前类别已有 importer，保留其他类别，维护窗口，打包一次，并在任何远端写入前持久化包字节和预期父身份。同日不同内容摘要是明确修订，不能改成另一个报告日期。

持久阶段至少区分 prepared、asset_uploaded、dispatched、deployed、verified、admitted、archived，记录每阶段覆盖的真实字节和远端身份。只有部署及线上核对通过，才用预期父身份比较并更新当前快照。另一个报告类别等待或推进已有候选，不能基于过时父快照另造新包。

上传/dispatch 超时先查询远端再重试。模糊或冲突身份必须拒绝。构建失败、线上摘要不符、日期过期、run 被取消都不能生成成功回执。按 Deploy 原归档契约永久保留原输入/清单、包、构建/质量身份、部署及真实验证结果。

若远端已部署而本地尚未确认即崩溃，通过 pending、run 回执及线上标记恢复，不能重新 bootstrap 旧内容或省略核对。仅更新源码时保留报告字节和身份，只更新渲染器。

周报图片投递仍是原有独立操作，只有匹配的已验证周报发布回执才能允许投递；开发验收不发送消息。报告新鲜度监控仍归 Deploy。

## 兼容、启用与回滚

显式生产变更前默认保持旧模式。不改写/删除历史报告、Git 历史、回执，不重命名旧状态字段、清空 pending、改共享 hook 或为测试修改生产服务。

交付包括配置模板、切换前排空检查、无发送合成冒烟、稳定 release 指南及具体回滚流程。生产文件/timer/current、仓库模式变量和真实发布按仓库要求另行授权；待代码和切换方案可核查后再处理该最后一步。源码审阅和合并已有持续授权。

回滚需要固定的旧渲染器/发布器和经过协调的归档公开快照。不能简单重启旧 push workflow，让 Git 旧输入覆盖最新日报。保留最近已验证内容和前一个已验证 release。

## 验收

- 内容包精确往返、规范化身份、公开白名单、全部报告类别、缺失/空值、边界限制；恶意路径/链接/重名/压缩炸弹/未知字段不产生部分提升。
- 外部输入构建保留源码干净状态、固定 exporter 来源、真实字节、质量身份、中英文链接、报告/下载路由及失败前输出。
- 仅源码更新不改变最新报告；美股/亚洲/周报交错更新互不丢失，同日修订和窗口正确。
- 上传、dispatch、部署、核对各阶段故障可恢复，响应丢失不重复发布，旧父身份不能更新当前状态，旧 pending/回执原样保留。
- 合并前完成各 owner 完整相关门禁、已安装 owner CLI 检查及本地合成站点的真实隔离浏览器验收。
- 合成验收不生成真实报告、不改生产定时/配置、不上传真实 asset、不 dispatch 生产部署、不发送消息。
